# B 机借助 A 机网络上网（UU远程端口映射 + 双协议代理）

## 架构

```
┌─────────────────────┐         UU远程 隧道(端口映射)         ┌──────────────────────────┐
│  B 机（远程机）      │  127.0.0.1:10800 ════════════════▶  │  A 机（本机，网络出口）    │
│  系统代理指向        │        B 的本地端口 → A 的端口        │  dual_proxy.py 监听       │
│  127.0.0.1:10800    │                                     │  127.0.0.1:10800          │
└─────────────────────┘                                     └──────────┬───────────────┘
                                                                       │ 正常出口上网
                                                                       ▼
                                                                   互联网
```

B 机的所有代理流量经 UU远程 隧道送到 A 机，由 A 机代为访问互联网后原路返回。

## 文件清单

| 文件 | 用在哪台机 | 作用 |
|---|---|---|
| `dual_proxy.py` | A 机 | 双协议代理服务器（SOCKS5 + HTTP，单端口，纯 Python 标准库）；内置 Web 状态面板 |
| `start_proxy_A.bat` | A 机 | 一键启动代理 |
| `open_dashboard.bat` | A 机 | 一键打开可视化状态面板（浏览器） |
| `set_proxy_B.bat` | B 机 | 一键开启 Windows 系统代理 |
| `clear_proxy_B.bat` | B 机 | 一键关闭系统代理（恢复 B 自身网络） |
| `proxy_switch_B.hta` | B 机 | **图形界面开关**（推荐）：双击运行，窗口内一键开启/关闭，并测试 A 机连通性；无需 Python |
| `launch_via_A.bat` | B 机 | 仅让"被它启动的那一个应用"走 A（不改系统代理），其余应用照常用 B 本机网络 |
| `browser_via_A.bat` | B 机 | **仅浏览器走 A 的专用启动器**（不改系统代理）：双击即用 A 的网络开一个独立 Chrome/Edge/Firefox |
| `proxy_extension/` | B 机 | **浏览器扩展（插件）**：工具栏图标一键切换走 A / 本机，并显示实时连接状态（出口 IP / 连不上 A），只影响该浏览器 |
| `proxy_A_app.py` | A 机 | 打包外壳（自动开面板 + 停止按钮，无 tkinter 依赖） |
| `build_A_app.bat` | A 机 | 一键把代理打包成 `dist/proxyA.exe`（需本机有 Python + 可联网装 PyInstaller） |
| `dist/proxyA.exe` | 任意机 | **已生成的独立 exe**，无需 Python，拷到 C 等电脑双击即用 |

## 打包成独立 exe（在 C 电脑运行）

目标：把 A 机脚本打包成 **`proxyA.exe`**，目标机器（如 C 电脑）**无需安装 Python**，双击即用。

**已为你生成**：`dist/proxyA.exe`（约 8.6MB，已内嵌 Python 运行时与代理代码）。直接拷到 C 电脑即可运行。

**运行方式（C 电脑）**：
1. 把 `dist/proxyA.exe` 拷到 C，双击运行。
2. 它会自动用默认浏览器打开状态面板 `http://127.0.0.1:10801/`。
3. 面板里有「停止代理」按钮，点一下即关闭程序（也可在任务管理器结束 `proxyA.exe`）。

**自己重新打包**（本机需有 Python 3.7+ 且能联网装 PyInstaller）：
- 双击 `build_A_app.bat`；或手动执行：
  ```bash
  python -m PyInstaller --onefile --noconsole --name proxyA proxy_A_app.py
  ```
  产物在 `dist/proxyA.exe`。

> 注：打包外壳 `proxy_A_app.py` 用「浏览器面板」作为界面（无 tkinter 依赖），所以任意 Windows 都能打包运行。

### 在 C 电脑充当出口机时
- C 运行 `proxyA.exe` 后，C 即成为此前的「A 机」角色（网络出口）。
- **UU远程端口映射要指向 C 的 10800**（即 B 的 `127.0.0.1:10800` → C 的 `127.0.0.1:10800`）。
- B 机配置不变：代理仍指向 `127.0.0.1:10800`。

## 可视化状态面板（推荐）

代理启动后自带一个本地 Web 面板，**在 A 机浏览器打开 `http://127.0.0.1:10801/`** 即可实时看到：

- 运行状态（运行中 / 无法连接）
- 监听地址、已运行时长
- 累计连接数、当前活跃连接数
- 最近连接明细（时间 / 协议 / 客户端 / 目标），每 1 秒自动刷新

双击 `open_dashboard.bat` 也可直接唤起浏览器打开面板。
关闭代理窗口后面板将无法连接——此时即代表代理已停止。

> 不需要面板可加 `--no-panel` 或 `--web-port 0` 关闭；面板默认端口 10801，若被占用代理仍会正常运行，仅面板不可用。

## 配置步骤

### 第 1 步：A 机启动代理

1. A 机安装 Python 3.7+（安装时勾选 *Add Python to PATH*）。
2. 把 `dual_proxy.py` 和 `start_proxy_A.bat` 放到 A 机同一目录，双击 `start_proxy_A.bat`。
3. 看到「双协议代理已启动」即成功，窗口保持开着（可最小化）。

### 第 2 步：UU远程设置端口映射

> 目标只有一个：**B 机上访问 `127.0.0.1:10800` 的流量，要被转发到 A 机的 `127.0.0.1:10800`。**

1. 打开 UU远程，找到「端口映射」功能（一般在 设备/会话 的设置里，具体入口以当前版本为准）。
2. 新增映射，方向必须是 **B 的本地端口 → A 的端口**：
   - 被控端（A 机）地址：`127.0.0.1`，端口 `10800`
   - 主控端（B 机）本地端口：`10800`
3. 也就是说：需要由 **B 远程连接 A**（B 为主控、A 为被控），UU远程端口映射默认正是把被控端的服务映射到主控端本地。
4. 如果你的 UU远程版本映射方向相反（只支持把被控端服务映射给主控端访问，而你实际是 A 控制 B），则把代理跑在能被映射到 B 的那一侧即可——原则不变：**B 的 127.0.0.1:10800 必须能连通代理**。

### 第 3 步：B 机开启系统代理（推荐用图形界面）

**更简单的方式**：把 `proxy_switch_B.hta` 拷到 B 机，双击即用——窗口里有「开启 / 关闭」按钮，还能一键「测试 A 机代理连通性」，无需命令行、无需 Python。

**或用 bat（无 GUI 环境）**：把 `set_proxy_B.bat`、`clear_proxy_B.bat` 拷到 B 机，双击 `set_proxy_B.bat`，再重启浏览器生效。
3. 验证（Windows 10/11 自带 curl，在 B 机执行）：

```bash
curl -x socks5h://127.0.0.1:10800 http://myip.ipip.net     # 应显示 A 机的公网 IP
curl -x http://127.0.0.1:10800 https://myip.ipip.net       # 同上
```

浏览器访问 `https://myip.ipip.net`，显示 A 机 IP 即成功。

### 最常见场景：只有浏览器走 A，其它应用走本地

如果你只想让浏览器借 A 上网、B 机上的其它软件（微信、游戏、下载器等）继续用 B 自己的网络，**关键是：不要开启 Windows 系统代理**（即不要用 `set_proxy_B.bat`，也不要点 HTA 的「开启」按钮）。

做法：把 `browser_via_A.bat` 拷到 B 机，双击即用 A 的网络打开一个**独立实例**的浏览器：

```bash
browser_via_A.bat          # 用 A 的网络打开 Chrome（默认）
browser_via_A.bat edge     # 改用 Microsoft Edge
browser_via_A.bat firefox  # 改用 Firefox
```

原理：脚本只给这个浏览器进程传 `--proxy-server=socks5://127.0.0.1:10800`，**完全不动系统代理**，所以机器上其余应用照常走 B 本机网络。由于用了独立用户目录（`--user-data-dir`），即使你平时已在用 Chrome，这次也会是隔离的新窗口，确保代理参数一定生效（否则 Chrome 单实例会忽略新启动的代理参数）。

> 验证：在该浏览器打开 `https://myip.ipip.net` 应显示 A 机 IP；而在 B 机其它软件 / 另一个没走代理的浏览器里查 IP，应仍是 B 机自己的 IP。

**不用脚本也行**——给浏览器快捷方式「属性 → 目标」末尾追加：
```
--proxy-server="socks5://127.0.0.1:10800"
```
然后只从这个快捷方式启动浏览器即可。

**Firefox 注意**：它不认 `--proxy-server` 参数。用 `browser_via_A.bat firefox` 打开后，还需在 Firefox 内手动设一次：设置 → 网络设置 → 手动代理配置 → SOCKS 主机填 `127.0.0.1`、端口 `10800`，并勾选「代理 DNS 请求」。

### 另一种做法：浏览器扩展（插件）形式

如果你更习惯"点一下工具栏图标就开关"，可以装一个浏览器扩展 `proxy_extension/`（Chrome / Edge / Firefox 通用，纯本地、无需联网、无需 Python）：

- 点工具栏图标弹出小窗，**实时显示连接状态**：开关状态（走 A / 本机）+ 连接状态（`● 已连接 A，出口 IP：x.x.x.x` 或 `✕ 代理已开但连不上 A`）。
- 连接状态通过真实外网出口 IP 检测得到——显示 A 的 IP 即代表链路通，显示"连不上 A"即代表 A 机没运行或 UU映射未生效。状态每 8 秒自动刷新，也可点「刷新连接状态」。
- 连接状态还会显示**对端机器名**（A 机的 hostname，如 `● 已连接 A（对端：DESKTOP-XXX），出口 IP：…`）。前提：① 在 UU映射里**额外**把 B 的 `10801` → A 的 `10801` 也加上（A 机状态面板端口）；② A 机运行的是最新版 `dual_proxy.py` / `proxyA.exe`（已含机器名字段）。未映射 10801 时仅显示 IP，不影响使用。
- 一个按钮即可切换开关；扩展只在当前浏览器内设置代理，**完全不动系统代理**，所以其它应用照常走本地；重开浏览器会记住上次开关状态。
- 已内置 **SOCKS5 远程 DNS 解析**：`background.js` 的代理规则带 `proxyDNS: true`，Firefox 下 DNS 走 A 端解析（不泄露到 B 本地）；Chrome/Edge 本就默认远程解析。无需再手动勾选 "Proxy DNS via SOCKS"。
- 内置 bypass：`127.0.0.1` / `localhost` 直连（不影响你访问本地面板等）。

安装（开发者模式加载，无需上架）：
- **Chrome / Edge**：地址栏打开 `chrome://extensions`（Edge 为 `edge://extensions`）→ 右上角开「开发者模式」→ 点「加载已解压的扩展程序」→ 选择本仓库的 `proxy_extension` 文件夹。
- **Firefox**：地址栏打开 `about:debugging#/runtime/this-firefox` → 「临时载入附加组件」→ 选 `proxy_extension/manifest.json`。

载入后点工具栏图标即可开关；在浏览器打开 `https://myip.ipip.net` 验证是否显示 A 机 IP。

> 注意：Firefox 的临时加载在重启浏览器后会失效，需重新载入（或正式签名打包）。Chrome / Edge 开发者模式加载的扩展重启后保留。

### 恢复 B 机自身网络

双击 `clear_proxy_B.bat`。

### 进阶：仅指定应用走 A，其余走本地网络

Windows 的系统代理是**全局**的——`set_proxy_B.bat` 一开，B 机所有应用都走 A。若只想让特定应用走 A、其它应用照常用 B 自己的网络，有两条路：

**方案 1（免费，推荐）：用启动器只给指定应用挂代理**

新增 `launch_via_A.bat`：它**不改系统代理**，只启动"那一个应用"并让它走 `127.0.0.1:10800`，其余系统不受影响。若只要"浏览器"走 A，直接用更省事的 `browser_via_A.bat`（浏览器专用启动器，见上一节）。

```bash
launch_via_A.bat                          # 默认用 A 的网络打开 Chrome
launch_via_A.bat "X:\path\to\app.exe"     # 用 A 的网络打开指定程序
```

原理：给被启动的进程注入 `http_proxy`/`ALL_PROXY` 等环境变量（多数命令行/开发工具认），Chrome/Edge 额外加 `--proxy-server` 参数。系统代理保持关闭即可。

**方案 2（最省心，专业做法）：Proxifier**

装 Proxifier（Windows，有试用），加 Proxy Server `127.0.0.1:10800`（SOCKS5），再建规则：
- 指定 `.exe` → 走该代理
- 默认 → Direct（直连，走 B 本机）

系统代理保持关闭。这样完全是"按应用分流"，图形界面好管理。

> 提醒：若用方案 1/2，就**不要再点 `set_proxy_B.bat` 开全局代理**，否则又会全走 A。

## 原理说明

- `dual_proxy.py` 在同一端口同时支持 **SOCKS5** 与 **HTTP 代理**（含 HTTPS 的 CONNECT 隧道），因此浏览器、curl、各种支持代理的软件都能直接用。
- **域名在 A 机侧解析**（SOCKS5h / HTTP CONNECT 传域名），所以 B 机即使没有可用 DNS 也能正常打开网站。
- 代理只监听 `127.0.0.1`，不暴露到局域网，只有通过 UU远程映射进来的流量可达。

## 限制与注意

- 仅转发 **TCP**；UDP 流量（部分游戏、语音）不走此通道。
- 速度受 UU远程隧道带宽与稳定性限制。
- A 机的代理窗口和 UU远程映射必须保持在线，任一断开则 B 机无法上网（记得先运行 `clear_proxy_B.bat` 再关闭，否则 B 机网络会"假死"）。
- 系统代理对个别不走系统代理的应用无效（如某些命令行工具），这类应用可在其自身设置里单独配置 SOCKS5 `127.0.0.1:10800`。

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| B 机 curl 直接连 `127.0.0.1:10800` 都失败 | UU远程端口映射未生效或方向配反了，检查第 2 步 |
| 映射通但上网 502 / SOCKS5 连接失败 | A 机代理没启动，或 A 机自身访问该网站也失败（在 A 机浏览器验证） |
| 10800 端口被占用 | 换端口：A 机 `python dual_proxy.py --port 1080`，同时 UU映射和 B 机脚本里的端口同步改 |
| 部分应用不走代理 | 该应用不读系统代理设置，在其内部单独配置 SOCKS5 `127.0.0.1:10800` |
| 想看代理在忙什么 | A 机用 `python dual_proxy.py -v` 启动，输出调试日志 |
